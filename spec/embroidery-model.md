# Модель вышивки: минимальное проверяемое ядро

Статус: целевая модель с первым реализованным срезом, 16.09.2026. Исходный аудит §7 относится к `cccc814`; текущие изменения перечислены ниже.
Цель — воспроизвести действия выбранного рецепта и получить проверяемый путь нити; полная физическая достоверность не заявляется.
Ремесленные основания и границы вариантов: [craft-sources.md](craft-sources.md). Одна красивая итоговая картинка не закрывает приёмку.

## Реализованный срез 16 сентября

- `motifSupport` — единая проверка доступности рецепта; неподдерживаемые компиляции завершаются `UnsupportedPatternError`. C8/C10 больше не получают fallback кику, хоси/хиси/оби не запускают заглушки. Доступность Simple 8 не означает полную физическую верификацию.
- `local-marking.ts` выводит лучи из реальных окружностей с явными первым лучом и направлением обхода; объединяет нормали modulo ± и возвращает точки в миллиметрах при переданном обхвате. Проверены все центры S8/C8/C10, неравномерные углы, знаки нормалей и совместные повороты. Полный граф рёбер ещё не введён.
- `c8-engineering-coupon.ts` задаёт одну группу, восемь идеальных меток и четыре наружных острия. C=230, inner=5, outer=20 мм — инженерный fixture, не размеры GT55. `lab.html` показывает только порядок геодезических соединений, не физический путь нити.
- Старый Simple 8 пока работает через прежний компилятор/рендер. Его мировые поправки, контакты и фиксированная калибровка C24 остаются ограничениями. Дедупликация C10 исправлена только в новом адаптере, не в старом отображении/метраже.

Следующий срез: одна рабочая нить с явными подхватами, скрытыми переходами и подготовительными опорами C8; прежде чем включать рецепт в мастерской, проверить её полный путь и контакты.

## 1. Область первого результата

1. Контрольный S8: зафиксировать конкретный рецепт, A1 → B1 → A2, места подхвата и переходы двух рабочих нитей.
2. Один центр C8: отдельный контрольный образец выбранной операции с явно заданной предварительной вышивкой.
3. Шесть центров C8: общая хронология, взаимодействие цветов, переходы и завершения; затем проверка всей композиции.
4. Один центр C10 и двенадцать центров: только после выбора своего рецепта; геометрия разметки сама поддержки не даёт.
GT55 задаёт одну группу на восьми лучах: четыре внешние точки и четыре внутренние; переносить в него два набора GT14 нельзя.
Предварительные ромбы/треугольники GT55 — часть рецепта. Образец одного центра с подставленной предварительной вышивкой не является готовым GT55.
Число лучей, внешних точек, групп, рабочих нитей и цветов — разные данные; одинаковый цвет не означает одну физическую нить.

## 2. Границы ответственности и контракт данных

```ts
type Mm = number & { readonly unit: 'mm' };
type Unit3 = readonly [number, number, number]; // unit length, validated
type PointMm = readonly [Mm, Mm, Mm];
type Ref = string; // stable ID, not array position or world-axis label
type Evidence = { source: Ref; locator: string; status: 'sourced'|'assumption'|'measured' };
type Body = { circumferenceMm: Mm; radiusMm: Mm; surface: 'sphere' };
type MarkingGraph = {
  nodes: { id: Ref; p: Unit3 }[];
  circles: { id: Ref; normal: Unit3 }[]; // unoriented plane: n and -n are identical
  edges: { id: Ref; circle: Ref; from: Ref; to: Ref; sweepRad: number }[];
  incidences: { node: Ref; edge: Ref; tangent: Unit3 }[];
};
type Placement = {
  center: Ref; rays: Ref[]; firstRay: Ref; handedness: 1|-1;
  domain: DomainPolicy; // explicit composition boundary, not implicit hemisphere
};
type Recipe = {
  id: Ref; version: string; evidence: Evidence[];
  requires: { division: Ref; rayCount: number; priorFeatures: Ref[] };
  marks: MarkRule[]; groups: GroupRule[]; stop: StopRule; transitions: TransitionRule[];
};
type GroupRule = {
  id: Ref; rayWalk: { ray: number; mark: Ref }[]; rows: RowRule;
  threadPolicy: ThreadRule; catchRule: CatchRule;
};
type NeedleOp = { id: Ref; order: number; thread: Ref } & (
  | { kind: 'start'|'finish'; anchorRoute: RouteSpec }
  | { kind: 'lay'|'transfer'; from: Ref; to: Ref; route: RouteSpec }
  | { kind: 'catch'; enter: Ref; exit: Ref; capture: Ref[]; pass: 'over'|'under'; route: RouteSpec }
  | { kind: 'park'|'resume'; at: Ref }
);
type WorkingThread = { id: Ref; material: Ref; events: Ref[]; state: 'active'|'parked'|'finished' };
type PathSpan = { id: Ref; thread: Ref; op: Ref; curve: CurveMm; zone: 'surface'|'buried'|'free' };
type Contact = { spans: [Ref,Ref]; at: [number,number]; over: Ref; clearanceMm: Mm };
type ThreadPath = { spans: PathSpan[]; contacts: Contact[]; section: CrossSection; diagnostics: Diagnostic[] };
compile(recipe, graph, placements, body, priorState): Result<NeedleOp[], Unsupported|InvalidRecipe>;
resolvePaths(ops, threads, body, material, priorPaths): Result<ThreadPath[], ConstraintFailure>;
render(paths, camera, light, tessellation): Mesh; // cannot change paths or sewing order
```

`MarkRule` хранит расстояние вдоль конкретного луча либо долю именованного интервала разметки; единицы и направление обязательны.
`RowRule` описывает развитие внутренней/внешней точки и прилегание к предыдущему ряду; все численные параметры имеют происхождение.
`RouteSpec` различает укладку, подповерхностный проход и свободный рабочий конец; для неоднозначной дуги содержит промежуточную опору.
`CatchRule` называет захватываемые линии разметки/старые стежки и сторону обхода, а не только высоту декоративного бугорка.
Один общий компилятор допустим для всех центров и нескольких рецептов, если набор операций достаточен и каждый рецепт проверен.
Новый центр — новая привязка; новый ремесленный вариант — новые данные и, только при необходимости, новая операция.

## 3. Геометрия разметки, центр и область

Пусть `R = C/(2π)` в миллиметрах, `p,q ∈ S²`. Расстояние по основе:
`dS(p,q) = R atan2(||p×q||, p·q)`; евклидово расстояние объёмных нитей вычисляется отдельно в `PointMm`.
Луч в центре `c` — ориентированная касательная `t`, `t·c=0`, полученная из инцидентной линии разметки.
Точка на нём: `x(s)=R[c cos(s/R)+t sin(s/R)]`. Для большого круга с нормалью `n` проверяется `n·x=0`.
Локальный базис: `e1=t(firstRay)`, `e2=handedness(c×e1)`; углы остальных лучей определяются относительно него.
Циклический порядок лучей идёт из геометрии, начальный луч и направление обхода — из рецепта; мировой Y не несёт ремесленного смысла.
Две нормали задают один круг, если `|n·m|≈1`; дедупликация должна работать и на границах выбора знака нормали.
Разметочный граф включает пересечения, сегменты и инцидентность. Нарисованные шейдером грани и произвольные snap-точки его не заменяют.
Для C8 проверяются шесть восьмилучевых центров; для правильного C10 — двенадцать десятилучевых центров.
`DomainPolicy` может задавать границу по линиям, соседним мотивам, поясу либо явные разрешённые перекрытия.
Сферическая ячейка Вороного — допустимый выбор конкретной композиции, не универсальный закон темари.
Для одинаковых соседей половина расстояния между центрами даёт консервативный радиус непересекающихся круглых областей.
Это `πR/4` для соседей C8 и `R acos(1/√5)/2` для соседей C10; цветок может иметь некруглую область и другие правила.
Наличие диаметра нити требует отступа от выбранной границы; область проверяется по всему пути, а не только по внешним меткам.
Совпадающие и антиподальные точки требуют явного разбора: у антиподов кратчайший путь не единственен, случайная мировая ось не подходит.

## 4. Игла, хронология и непрерывная рабочая нить

Операция иглы и уложенный участок нити связаны, но не тождественны: подхват содержит вход, выход, захваченный объект и трассу между ними.
После `lay` конец пути совпадает с входом следующего `catch`; его выход является началом следующего укладываемого участка.
`park/resume` сохраняют `threadId` и конец нити; переход к новому ряду задаётся явно, включая скрытый участок, если он нужен.
Переключение A → B — смена активной рабочей нити. Возврат в исходную точку не сваривает нить в замкнутое кольцо.
`start/finish` задают закрепление и погружённый путь; смена цвета либо исчерпание длины не могут молча разрезать старую нить.
Порядок операций общий для всех центров; предварительная вышивка участвует в контактах наравне с текущим мотивом.
Новый участок обычно ложится поверх уже уложенного согласно рецепту; проход под ним требует соответствующего `catch/transfer`.
Идентичность рабочей нити определяется событиями, а не близостью концов, цветом или одинаковыми `pole+set`.
Путь под основой нужен для непрерывности и метража даже при невидимости. Неизвестный маршрут остаётся явно неизвестным.

## 5. Толщина, контакты и пределы физической модели

Первое ядро — последовательная геометрическая модель уложенной нити с ограничениями контакта, приближение квазистатики.
Начальная проверяемая модель: круглый несжимаемый шнур радиуса `r`, сферическая поверхность основы, фиксированные места прихватов.
Для поверхностного участка `||x||≥R+r`; для несоседних участков `min(s,t)||x_i(s)-x_j(t)||≥r_i+r_j`.
Соседство исключается только в локальной окрестности одного непрерывного стыка; далёкие участки той же нити тоже проверяются.
Исключение соседей не разрешает складку трубы: для гладкой центральной линии круглого несжимаемого шнура локально требуется `r·κ<1`, где κ — кривизна. Это условие регулярности выбранной геометрической трубы, не измеренный минимальный радиус сгиба реальной пряжи; глобальную самопересекаемость проверяют отдельно. Угловые стыки должны получить явный сгиб либо диагностику.
Погружённые участки имеют отдельный допустимый слой основы и точки входа/выхода; общее ограничение внешней поверхности к ним неприменимо.
На заданном пересечении проверяется также сторона `over` по локальной нормали поверхности. Одной минимальной дистанции для этого недостаточно.
Контакты ищутся по сегментам/капсулам с контролем погрешности аппроксимации кривой; сравнение только дискретных вершин пропускает пересечения.
Обнаружение включает все центры, группы и маркировочные нити. Пространственный индекс допустим, фильтр `samePole` — нет.
Корректируется новый путь относительно уже разрешённой геометрии нижних нитей; сумма «число нитей × высота бугорка» не определяет контакт.
После любого подъёма/сдвига повторно проверяются соседние контакты, опоры, границы и непрерывность; неразрешимый случай возвращает диагностику.
Сначала достаточно локального детерминированного решения ограничений. Утверждать механическое равновесие без силовой модели нельзя.
Прямой участок на гладкой сфере без боковых ограничений может идти по геодезической; плотный ряд требует контактов/трения и не обязан ей быть.
Гибкость, трение, натяжение, овальное сечение и сжатие вводятся позже только с источником параметров и измеримым целевым эффектом.
При сжатии `r` нельзя просто уменьшать до красивого изображения: нужна явная модель допустимой деформации и её проверка.
Настоящая квазистатика решает равновесие после шага; динамика дополнительно вводит массу, скорость и изменение во времени.
Динамика нужна при доказанной потребности моделировать протягивание, проскальзывание или провисание; для первого образца она не обязательна.
Renderer строит сечение вокруг уже рассчитанной центральной линии; LOD и свет не меняют радиус, контакты, длину и хронологию.

## 6. Инварианты, допуски и метраж

Для любого `Q∈SO(3)` совместно поворачиваются тело, граф, лучи, опоры и пути: `F(Q input)=Q F(input)`.
Сравнение производится по идентификаторам событий/параметрам кривых с учётом разрешённой перенумерации симметричных центров.
Поворот только центра при сохранении числа `phi` в старом мировом базисе этому условию не соответствует.
При масштабировании всех длин на `λ` форма и контакты масштабируются на `λ`; при изменении только C с прежней нитью число рядов может меняться.
Вычислительная точность, погрешность дискретизации и неопределённость материала — три отдельных бюджета, с единицами и областью применения.
Для аналитических тестов S² стартовый бюджет `1e-10` безразмерный; для путей бюджет задаётся в мм и проверяется при удвоении разрешения.
Это инженерные допуски вычисления, не экспериментально подтверждённая точность ремесла. Порог сжатия/прихвата требует отдельной калибровки.
Метраж центральной линии: `L_laid = Σ∫||dx/du||du` по поверхностным и погружённым участкам; диаметр не подменяет радиус основы.
Для простой дуги на радиусе `R+r`: `L=(R+r)θ`; для общего разрешённого пути нужна длина самой кривой, а не сумма исходных дуг на S².
`L_cut=L_laid+L_tails+L_unlaid` считается по рабочим нитям; свободные/обрезанные концы учитываются ровно один раз.
Если скрытый маршрут неизвестен, показывать частичную длину или диапазон с допущениями. Закупочный запас — отдельная оценка, не «точный расход».

## 7. Точечный аудит и read-only эксперименты

Вызовы исполнены 16.09.2026 Node 24 через stdin, без записи/изменения исходников; импортированы текущие `patterns.ts`, `kagari.ts`, `jiwari.ts`, `measure.ts`.
Воспроизведение: [scripts/inspect-embroidery-model.mjs](../scripts/inspect-embroidery-model.mjs), из корня проекта `node --experimental-strip-types scripts/inspect-embroidery-model.mjs` на Node 24.
Скрипт только читает исходники/Git и печатает JSON со снимком, SHA256 и версией Node. Это диагностика, не production acceptance: численные наблюдения текущих дефектов ожидаемо изменятся после реализации; assertions проверяют только независимые тождества предлагаемой формулы луча.
`patterns.frame/around` выбирают базис по мировым осям: функция математически определена, но её входов недостаточно для переноса привязанного к разметке цветка.
`stitches.poleBlend`, ограничение высоты и сплющивание сечения зависят от `abs(y)`; `kagari.innerBiteJoin/clampNotPastPole` тоже выбирают мировой полюс.
`annotateSetCrossings` исключает другой `pole` и ту же группу, ищет ближайшие выборочные точки; это ограничение текущей реализации, не ремесла.
Поправки B/A задаются `sitAts`, `stackBump`, `STACK_LIFT=0.92`, затем подавляются у Y-полюса; итогового ограничения расстояния между шнурами нет.
`unitFromMm` принимает C, но потребители вышивки вызывают его с C24 по умолчанию; это фиксированная калибровка, не проверенная поддержка разных размеров.
На исходном снимке `kikuRecipe(c8)=null`, однако `compileKiku(c8, out, even, 0, 0, 1)` возвращал 16 операций. В первом реализованном срезе fallback удалён: этот вызов явно отклоняется, диагностика сообщает отсутствие поддержки.

| Проверка | Численный результат | Следствие |
|---|---|---|
| `jiwariNormals(c10)`, объединение по `abs(dot)>1−1e−12` | 16 записей, 15 уникальных плоскостей; повторный индекс 11; у всех 12 центров по 10 лучей | Исправить дедупликацию и получать метраж из реального графа, не константы 16 |
| `p=(0,1,0)`, `Q(x,y,z)=(y,−x,z)`, `θ=.3`, `φ=.7` | `||Q around(p)−around(Qp)||=.5910404`, или 22.5761 мм при C24 | Нужны повёрнутые лучи/базис; этот тест выявляет недостаток контракта, а не ошибку формулы around |
| `innerBiteJoin`, те же Q и pearl=.71 мм | Максимальное расхождение соответствующих точек 0.514126 мм при C24 | Сам подхват имеет независимую зависимость от мировой оси |

Для подхвата взяты нормированные `from=(.055,.987,.14)`, `mark=(.04,.99,.12)`, `to=(.025,.987,.155)`, умноженные на `1+unitFromMm(.71)/2`, `n=4`.
Дополнительно: одинаково пересекающиеся дуги аннотируются при одном pole и пропускаются при разных; смена только метаданных меняет результат.
Контроль: дуги между нормированными `(-.3,1,0)→(.3,1,0)` и `(0,1,-.3)→(0,1,.3)`, группы 0/1, ряд 0.
Текущая конверсия `unitFromMm(1)` на сфере C32 соответствует 1.333333 мм; `unitFromMm(1,32)` соответствует 1 мм.
У `closestApproachT` отрезки `(-1,0,0)→(1,0,0)` и `(0,-1,0)→(0,1,0)` дают `√2`, хотя пересекаются: изолированный тест алгоритма выборки, не стежок на сфере.
Положительный контроль предлагаемой формулы `p cosθ+t sinθ`: при совместном повороте p и t в 100 случаях ошибка ≤`3.85e−16` на S².
Для этого контроля `p=normalize(.1,.9,.3)`, `t=normalize(p×(.3,.2,.8))`, ось `normalize(1,2,3)`, углы поворота `.173k`, `θ=.01+.009k`, `k=0…99`.
Минимальные расстояния центров из текущего `division.ts`: C8 `1.5707963268` рад, C10 `1.1071487178` рад; последнее совпадает с `acos(1/√5)` до `2.3e−16`.

## 8. Миграция и приёмка

1. Сохранить React/Three, каталог и проверенные операции на сфере; ввести явный результат поддержки без геометрических fallback для C8/C10.
2. Добавить граф и `Placement` адаптерами к существующей разметке; исправить C10-дедупликацию, получать лучи из инцидентности.
3. Ввести размерный `Body` в новый путь компиляции. Старый S8 остаётся контрольным экземпляром C24, не источником универсальных констант.
4. Расширить `KagariOp` идентификаторами нитей, подхватами и переходами; сохранить адаптер в старый `Stitch` для промежуточной визуальной сверки.
5. Вынести разрешение пути и контактов из `stitches.ts`; убрать мировые полюсные поправки после замены явным локальным контрактом.
6. Сделать renderer потребителем `ThreadPath`; после сверки удалить дублирующие способы подъёма, склейки и расчёта пересечений.
7. Пройти S8 → C8-образец → шесть C8 → полная композиция → C10; тотальная перепись не является предварительным условием.

Приёмка каждого этапа требует следующих независимых проверок:
- **Рецепт:** ожидаемая таблица действий из источника; GT14 имеет A/B, GT55 не получает выдуманную B; prerequisites и остановка явны.
- **Разметка:** инцидентность каждой метки, правильные циклы лучей, уникальные круги modulo ±; после общего поворота свойства сохраняются.
- **Рабочая нить:** непрерывность вход/выход, ровно один start/finish у завершённой нити, park/resume без скрытого разреза, корректный префикс исполнения.
- **Контакты:** пересечение между центрами, внутри одной группы и между A/B; поздний участок над ранее поднятым; диагностируемая невозможная укладка.
- **Сгибы:** локальная кривизна не выворачивает выбранное сечение трубы; соседние сегменты не исключаются из этой проверки вместе с контактным фильтром.
- **Числа:** 90° и произвольные повороты, неодинаковое масштабирование шара/нити, устойчивость при сгущении выборки, метраж известных дуг и скрытых проходов.
- **Область:** граница проверяется по всем участкам; разрешённые перекрытия названы, отсутствие контактов не выводится из одной только дистанции центров.
- **Изображение:** первый стежок, группа/ряд, следующий ряд, заполнение и боковой ракурс; для S8 отдельно A1/B1. Расчётный путь сопоставлен с видимым.
- **Полнота:** шесть отдельных корректных цветов ещё не подтверждают переходы и предварительные элементы композиции; это отдельная проверка.

Остаётся выяснить: точный маршрут/длина закреплений, геометрия подхвата и опор GT55, фактическое сжатие и трение материала, рецепт C10.
Неопределённость источника не заменяется произвольным числом; допущение можно реализовать для образца, сохранив его статус и отдельный критерий проверки.
Ремесленная верификация по источнику, математическая корректность модели и художественная приёмка пользователем фиксируются раздельно.
