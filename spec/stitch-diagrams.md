# Иллюстрации из контрольного пути

Срез 19.09.2026, рабочая ветка `codex/temari-next`, задача [#49](https://github.com/newYurk/temari/issues/49). Новые виды заменяют первичное объяснение ранними ручными рисунками; старые SVG остаются в архиве.

## Что показано

Один изолированный нижний подхват из `computeLowerKagari()` с текущими параметрами по умолчанию. Это не полный цветок, не путь всей S8/C8-композиции и не физическое равновесие пряжи.

Два ортографических вида используют один и тот же `coupon`: по нормали к поверхности и с поворотом камеры на 55°. Проекция, масштаб и обрезка задают только вид; координаты, радиусы, шаги расчёта и параметры контакта не изменяются.

Показан крупный план: длинные ветви продолжаются за границей рисунка. Сетка фона является поверхностью для ориентации, не дополнительными нитями дзивари. Охра, синий и бордо обозначают части одной непрерывной рабочей нити. Маркеры 1/2 обозначают вход/выход вычислительного образца, 3 обозначает уход над приходом; это не булавки.

Пунктир строится по части заданного подхвата, ось которой находится внутри сферы. Переключатель скрывает/показывает её одновременно в обоих видах. Глубина не восстановлена по фотографии.

## Данные и проверка

`docs/fixtures/lower-kagari-diagram.json` хранит вычисленный путь, параметры, систему координат, порты, состояние проверок и SHA-256 геометрических зависимостей. Исходники модели не менялись для получения рисунков.

Новый канонический прогон C230 принят на 41 / 60 / 79 контрольных точках. На всех уровнях выполнены проверки полного пути, остановки и кривизны; максимальные соседние различия длины 0,0005501 мм и формы 0,0037281 мм укладываются в прежние допуски. Верхняя граница r·κ на последнем уровне около 0,8165361. Это численное свидетельство выбранного образца, не ремесленная приёмка.

Статические рисунки строятся через `evaluateCurve` и адаптивную выборку исходных кривых; порядок видимых сегментов определяется глубиной камеры. Координаты выносок не являются контрольными точками нити. Место перехлёста находится по проекции двух ветвей, а не рисуется отдельно.

Генератор отказывается использовать отклонённый, неразрешённый или устаревший снимок. При каждом `--check` заново проверяются путь и сертифицированная граница кривизны; оптимизация не запускается. Полный повторный расчёт выполняется отдельной командой.

## Воспроизведение

Требуется Node 24. Из корня репозитория:

```sh
# Только при изменении геометрических исходников или намеренном пересчёте:
npx tsx scripts/compute-stitch-diagram.mts

# Рисунки и публичные зеркала:
npx tsx scripts/build-stitch-diagrams.mts --write
node scripts/sync-design.mjs --write

# Быстрая проверка актуальности:
npx tsx scripts/build-stitch-diagrams.mts --check
node scripts/sync-design.mjs --check
npx tsx --test src/components/temari/stitch-diagram.test.ts
```

Скрипт меняет только выделенный блок `model-stitch-diagrams` в `public/design.html`. Не редактировать его пути вручную и не править зеркала отдельно. Сборщик не приписывает численную приёмку всему приложению.

## Границы приёмки

Проверены одинаковые мировые координаты в обоих видах, непрерывность, порядок над/под, проекции, отсутствие мутации исходных данных, управление скрытым проходом и браузерные ширины 1280/390/320.

Человеческая оценка понятности и ремесленной правильности остаётся открытой. Верхний охват пучка, следующие ряды и полная композиция должны получить собственные проверяемые иллюстрации, а не копию этого нижнего подхвата.
